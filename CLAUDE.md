# Правила проекта и стандарты разработки

Правила обязательны для разработчиков и AI-агентов и важнее стиля генератора и шаблонов
по умолчанию. Правила конкретного репозитория добавляются отдельным разделом в конце.

---

## 1. Код без поясняющих комментариев

Код самодокументируем: намерение выражают имена и структура, а не проза.

- **Запрещены комментарии, пересказывающие код**: `//`, `/* */`, `#`, `<!-- -->`, `{{-- --}}`
  с объяснением «что здесь происходит».
- **Docblock — только для типов**, которые нельзя выразить в языке (сложные дженерики, кортежи).
- **Непонятный код — повод для рефакторинга**, а не для комментария: переименовать,
  разбить на функции, вынести в модуль.
- **Исключение**: внешние ограничения, которые не вывести из кода (баг сторонней библиотеки
  со ссылкой, юридическое требование с URL, вынужденный обход с датой и причиной).

### 1.1. Имя вместо комментария

Комментарий над фрагментом — это недостающее имя.

- **Блок шаблона → компонент** с говорящим именем (`<MenuViews v-model="viewMode" />`
  вместо комментария над `<v-menu>`).
- **Шаг функции → функция**, названная тем, что говорил бы комментарий.
- **Растущая страница** делится на дочерние компоненты (разметка) и composables / хуки
  (состояние и логика). Общее состояние страницы — через provide/inject (или контекст),
  а не через длинные цепочки пропсов.

## 2. Размер файлов

- Ориентир — до 350 строк, жёсткий потолок — 400.
- Файл, перерастающий потолок, декомпозируется: доменная логика — в сервисы, actions,
  хелперы; разметка и UI-логика — в подкомпоненты и composables / хуки.
- Исключения: крупные таблицы конфигурации и сгенерированные артефакты.

---

## 3. Зависимости

- Только актуальные стабильные версии. Перед установкой — проверить текущую версию
  на `npmjs.com` / `packagist.org`, не брать версию из памяти.
- Deprecation-предупреждения устраняются сразу.
- Без пакетов за платной подпиской или с проприетарной лицензией.

---

## 4. Современный CSS

Без препроцессоров ради вложенности; только возможности стандарта:

- нативный CSS Nesting (`&:hover`, вложенные `@media` / `@container`);
- `:has()` вместо JS для стилей по состоянию потомков;
- container queries (`container-type: inline-size`) для переиспользуемых компонентов;
- `oklch()` для палитры, `color-mix()` для оттенков, `light-dark()` для тем;
- `@layer` для приоритетов, `subgrid` для выравнивания между карточками;
- `clamp()`, `min()`, `max()`, `round()` вместо лишних медиа-правил.

---

## 5. JavaScript / TypeScript

- Типы — отдельным `import type { … }`, без побочных эффектов.
- `array.at(i)`, `Object.hasOwn`, `structuredClone`, `flatMap`, `replaceAll`
  (это же требует `.oxlintrc.json`).
- Говорящие имена без сокращений (`user`, а не `u`; `documentRepository`, а не `repo`).
- Template refs во Vue — только `useTemplateRef('имя')`, не `ref(null)` / `ref<HTMLElement>()`.

---

## 6. Ошибки: никаких немых `catch`

Каждая перехваченная ошибка попадает в трекер (Bugsink / Sentry-совместимый SDK).

- Пустые `catch {}`, `.catch(() => {})`, `.catch(() => null)` запрещены.
- `catch`, который только пишет в консоль или молча возвращает значение по умолчанию,
  равен пустому.
- Единая точка отправки: в PHP — `report($exception)`, во фронтенде — `reportError(error)`,
  в промисах — `.catch(reportError)`.
- Пробрасываемую ошибку повторно не отправлять — её сообщит глобальный обработчик.
- Ожидаемые ошибки (отмена запроса, прерванная анимация, HTTP-ошибки) отсекаются внутри
  `reportError` или в `dontReport`, а не пропуском отправки на месте.

---

## 7. Инфраструктурные файлы

Без разрешения пользователя не менять `docker-compose*.yml`, `.env*` и подобные: от них
зависит локальный запуск. Это не касается `package.json`, `composer.json`, `go.mod`,
`Cargo.toml`.
